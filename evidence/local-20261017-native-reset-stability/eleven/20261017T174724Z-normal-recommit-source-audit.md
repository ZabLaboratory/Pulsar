## Finding

The exact reset fixture is an intentional forced load: `scripts/probe-group-composition-reset-exact.py:473-482,549-560` sends native `CommitGroupComposition` directly for generation 1 and then generation 2 with the *same* graph `planHash`. Its measured +9/+9/+12 immediate skipped frames in the three qualified instrumented runs (`20261017T173129Z`, `173223Z`, `173315Z` reset-exact JSONs) quantify this forced recommit. They do not measure how often normal Prism/Solar traffic recommits or prove a steady-state stall; each 20-second steady window added zero skips.

In the normal path, Orion forwards non-empty, wire-legal bound scalar deltas (`internal/lsdp/mirror.go:98-124,232-260`). Solar accepts the patched active scene and republishes its composition (`src/engine/native-lsdp-runtime.ts:293-307,636-643`; `src/engine/native-composition-session.ts:82-87,117-129`). Solar's publisher already suppresses a graph write when the producer and `planHash` match (`src/engine/native-composition-publisher.ts:348-360`). Prism coalesces watcher wakeups (`src/main/broadcast/engine/capture/program-graph.ts:629-684`) and suppresses a native commit when runtime, producer, Solar `planHash`, and `bindingSignature` match (`:832-860`). Repeated notification alone therefore does not imply a recommit.

A *possible normal* unchanged-native-geometry trigger is a bound text-default patch. Solar's existing unit test changes only `/defaults/__lit.text.title` and proves: accepted document/hash change; `NativeCompositionProjection` deep-equals the previous projection; Vision scene mounts once (`tests/unit/native-lsdp-runtime-composition.test.ts:261-330`). The projection equality is structural, not pixel equality: CEF text pixels may change. Solar's plan hash covers both the projection and the exact source `stateHash` (`src/scenes/native-composition-plan.ts:17-44`; publisher `:169-188`), so this patch changes the plan identity even with equal structural projection. Prism requires `plan.source.stateHash` to equal the *current* document hash and validates source/capture identity (`src/main/broadcast/engine/capture/native-composition-consumer.ts:680-722`); its binding snapshot can remain valid across document hashes when lane/runtime/producer/scene identity matches (`src/main/broadcast/engine/capture/mutations.ts:206-230`). The new Solar hash bypasses Prism's early guard. Prism's native wire hash also includes `sourcePlanHash` (`native-composition-consumer.ts:849-862`), so this revision changes the native `planHash` even if `groups` and replacement IDs are identical. Prism rereads both authorities before allocating a new generation and sending `CommitGroupComposition` (`program-graph.ts:1068-1123`). This last full-chain recommit is a source-code inference, not a measured real-session frequency or an existing end-to-end assertion.

There is a second possible over-sensitive guard: `bindingSignature` serializes the entire Main capture `appearance` (`program-graph.ts:832-852`). When a Solar capture occurrence provides `sourceFraming`, Main's `fit`, `contentBox`, `zoom`, and `contentPosition` are superseded by that occurrence (`:881-929`) and omitted from the effective wrapper `appearanceSignature` (`:932-960`). A refreshed Main binding changing only one of those overridden fields can defeat the early guard while reusing the same wrapper (`:977-1000`). This is a static possibility, not an observed normal producer frequency; `anchoring.ts:244-275` is the Main binding producer.

## Boundaries and minimal confirmation

Do not remove `stateHash` or `sourcePlanHash` from identity as a shortcut. They bind the Solar plan to the exact accepted LSDP document and the native receipt; dropping them would require a new provenance contract. Do not discard the whole binding signature: source/scene item IDs, source kind/device, replacement set, CEF atlas dimensions, and effective border/effects/framing can alter the native graph or appearance (`program-graph.ts:772-829,883-975`). Solar's plan includes ordered groups, surfaces, atlas size and coverage (`native-composition-plan.ts:23-44`); tests protect paint order, authored-vs-texture sizes, source framing, masks and coverage geometry (`tests/unit/native-composition.test.ts:172-198,234-248,393-422`; `native-composition-coverage.test.ts:122-143`; Prism `native-composition-consumer.test.ts:285-331` and `native-composition-coverage.test.ts:317-329`). CEF pixels can evolve without a structural change, and capture effects are Main-binding-owned; projection equality alone is not a complete render-state proof.

Smallest non-switch regression probe: keep one active lane, runtime, producer, CEF dimensions, capture bindings, group IDs and physical source fixed; apply the tested text-default scalar patch. Record the old/new Solar `stateHash` and `planHash`, Prism `bindingSignature`, native wire hash, wrapper IDs, generation and native Commit count *before* any screenshot/sleep. Assert structural projection equality, then establish whether normal Prism sends a second Commit and whether the wrapper is reused. A parallel binding-only case can change one Main `fit` value with explicit Solar `sourceFraming`, then check whether the same effective wrapper still incurs a Commit. These tests would establish incidence for the controlled trigger, not production frequency. For production frequency, add a low-cardinality reason counter at Prism's existing guard (source hash changed, binding signature changed, runtime/producer changed) and correlate with Commit receipts on active Preview and Live lanes. No product edit or GPU run was performed in this audit.
