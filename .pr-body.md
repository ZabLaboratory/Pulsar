## Summary

Bastion follow-up on #191 (issue #181): closes the residual ACL race left by the
first fix. `ofstream(trunc)` created `obs-websocket/config.json` under the
inherited (permissive) directory DACL and only restricted it *afterwards*
via `SetNamedSecurityInfoA` — leaving a window where a handle opened under
the old DACL survives the restriction and, because the file is truncated
(not replaced) on every subsequent boot, keeps reading every future
session password (R1/R2). Worse, `CREATE_ALWAYS` on a file an attacker
pre-created ahead of us keeps that file's existing security descriptor and
never applies our DACL at all (R3).

Fix: build the restricted, protected DACL first, then hand it to
`CreateFileA` via `SECURITY_ATTRIBUTES` with `CREATE_NEW`. The DACL is set
atomically at creation. If the file already exists: if it's owned by the
current account (ordinary reseed from a prior boot), delete and recreate
atomically; if owned by anyone else, refuse to write the password into it
and fail closed (logs the anomaly, matches the fail-closed posture in
#178).

Also fixes C4: the old comment claimed an ACL regression would be caught
via the probe script — that probe did not exist. `scripts/run-probes.ps1`
now asserts, after boot, that `config.json`'s DACL is protected and names
only the current account.

## Changes

- `plugins/pulsar-headless/main.cpp`: replace post-hoc
  `restrict_config_file_to_current_user` (ofstream + SetNamedSecurityInfoA)
  with `build_current_user_only_security_attributes` +
  `file_owned_by_current_user` + `CreateFileA(CREATE_NEW, ...)` in
  `seed_websocket_config`.
- `scripts/run-probes.ps1`: new ACL probe after `PULSAR_READY`, before
  Phase 2a — fails the suite if `config.json`'s DACL isn't protected and
  restricted to the current account.

## C3 / C4 / C6 status (Bastion follow-up on #191)

- **C3 (fixed)**: `CREATE_NEW` + pre-built protected DACL, atomic at
  creation. Pre-existing-file case handled per the seeding contract in
  `main.cpp:455-460` (own account -> delete+recreate; other account ->
  refuse, fail closed).
- **C4 (fixed)**: real ACL probe added to `run-probes.ps1`; the
  "confidentiality regression caught by the probe script" comment is now
  true instead of aspirational.
- **C6 (open, not verifiable from this environment)**: could not verify
  the real install directory's (`bin/64bit/`) DACL nor test cross-account
  read access under a second local Windows account — this agent session
  has no such second account or install-directory context. Declaring this
  a risk still open, same as Bastion's own report; needs a human or an
  agent with access to a real multi-account Windows box.
