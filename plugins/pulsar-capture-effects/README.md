# Pulsar capture effects

Scene-owned GPU filter `pulsar_capture_effects`, admitted by Prism's capture
appearance layer. It owns no physical device, audio route, scene switch or
transition. One filter per active authored capture accepts a bounded ordered
array of shadows, blurs, noise, texture and glass stages. Alpha is premultiplied.
The filter adds bounded transparent padding for external paint, and samples a
private mirror of lower scene items for backdrop/glass; it never renders the
parent scene recursively. Mirrors contain only preceding visible items and are
released with the filter. No inactive authored scene cache is retained.

Entry: src/capture-effects.cpp. Shader: src/capture-effects.effect, embedded at
build time. Public registration: pulsar_capture_effects. Consumer: Prism capture
resolver. Texture/glass remain procedural approximations like the authoring
model; glass adds GPU refraction, highlight and dispersion. Noise is stable in
object space. The host validates colors and bounds, the native entry clamps
again. Limits: 32 ordered effects, 100 px blur, 512 px transparent margin.

Standalone build accepts PULSAR_OBS_HEADERS and PULSAR_UPSTREAM_BUILD_DIR to use
an existing compatible libobs build. Standard Pulsar build includes this plugin.
Native acceptance requires real source screenshots, alpha/paint readback,
removal/reset, and coexistence with the native transition.

Fixed fixtures: `tests/capture-effects/fixtures/`, generated by
`tests/capture-effects/generate-fixtures.py`. The readback probe reuses the
existing obs-websocket protocol helper and requires Pillow/websockets:

```powershell
python scripts/probe-capture-effects.py --config <private-runtime-config> --output evidence/<issue>/<role>
```

Run against a disposable Pulsar runtime. It creates unique private fixture
inputs/scenes, checks registration and the pixels of all seven effects, verifies
filter removal, then removes its fixture sources in a finally block. It never
starts Live or recording. This proves GPU paint, not physical device availability.

`pulsar-capture-effects/CommitAppearance` reuses the native vendor API and
`obs_scene_atomic_update` on the graphics task queue. The commit validates
layer/input IDs, internal filter registrations and applies GPU settings, inner
fit, outer ROI position, zero crop, blend and visibility before a frame. A direct
reference stays visible until this admission removes it while preserving its
stack index. Updates to video filters are otherwise deferred by libobs; the
plugin synchronously admits its own settings before the transform is recalculated.
Zero stages still runs the initial ROI/rounding/opacity pass. There is no bitmap
or full-canvas renderer switch on clearing Effects. Retired internal color and
mask filters are removed only after checking their registration; physical and
operator filters remain untouched.

The probe also checks 80 rapid type/padding/empty-stack admissions, source size,
outer crop/position, stable preceding pixels, first-admission stack order and
refusal of a foreign filter collision. Those fixtures do not certify physical
window availability or every possible driver/GPU failure.

Authored rotation is admitted atomically with appearance. Nonzero angles use
centre alignment at x+width/2,y+height/2; zero restores top-left alignment at the
padding-adjusted origin. The inner fit is not rotated a second time. Backdrop
sampling maps local coordinates through this rotation into the scene. The probe
checks negative/positive angles, 90/180 degrees and reset with bounded padding.

`pulsar_object_blend` reuses this module's retained native backdrop prefix and
GPU passes for an isolated Solar object band. It implements the 16 W3C/CSS blend
modes (IDs shared with Vision), including non-separable hue/saturation/color/
luminosity. The shader outputs the source contribution only; normal alpha-over
adds the existing backdrop once. `CommitObjectBlend` validates the scene-owned
`ZabSolarBlend:<scene>:<band>` item and sets encoded-channel alpha compositing on
the graphics queue. It does not alter shared capture sources or the CEF input.
Current-scene layer removal releases the filter and prefix resources.
Capture appearance uses that same encoded-channel outer alpha-over method.
`settings.blend_mode` accepts the sixteen shader mode IDs; `blendMode` on the
outer item is normal. Gamma conversion of the premultiplied contribution is
disabled atomically in CommitAppearance, preserving partial opacity. The
capture fixture matrix compares 48 native cases (16 modes at 1/0.5/0 opacity)
against CSS pixels, with maximum channel error 1/255. It uses an image fixture
as the physical-input stand-in and does not certify device availability.
Pixel evidence covers opaque/translucent images and opacity 1/0.7 over a native
background, all 16 modes. This is separate from physical capture availability.

Authored framing uses crop_left/top/right/bottom percentages of original input,
content_x/y (0..1), and source_zoom (0.1..10), before the existing fit operation.
Opposite crop sides retain at least one percent of the input. The initial GPU
pass confines content to the authored box; clip_effects optionally reapplies
that rounded box after effects. Otherwise transparent padding preserves shadows
and blur outside the content box. CommitAppearance admits this geometry
atomically. video_tick recalculates crop/fit on first nonempty frame and input
resolution changes, without a new scene admission or physical-source mutation.
Native pixel proofs for image/video, actual camera vertical crop and delayed
first-frame arrival are in evidence/local-20261011-source-box/eleven/.

Independent content-box geometry uses content_box_x/y and content_box_width/height
in source-block pixels. The default remains the outer box. Cropping the outer box
retains the inner rectangle instead of refitting the source; panning supports both
axes at exact fit. Original-source crop, fit, zoom and alignment compose in the
inner rectangle. The initial ROI and design effects still use the outer block;
operator/physical capture filters remain on the upstream video. No frame source
or second physical input is created. Settings and both transforms are admitted
on the same graphics task, including first-frame and resolution-change handling.

Inherited frame clipping accepts up to 32 source-local affine rectangle projections
through ancestor_clips. Width/height/rounding are admitted with the existing
appearance settings; all ancestor coverage is applied inside the existing final GPU pass
following effects. Moving/rotating an ancestor does not reopen the physical source.
All sources retain their existing pass count, including clipped descendants. No bitmap,
new renderer, inactive scene cache or alternate lane path is introduced.

scripts/probe-capture-ancestor-clips.py uses disposable private sources to prove
translated/rotated rectangles, nested intersections, rounded and empty frames,
effect overflow clipping and exact reset. It never starts Live or recording.

The fresh proof covers seven effects, atomic paint updates, rotation and eight
ancestor-clip cases. Dependency binary hashes and the freshly built plugin hash

Native group composition is admitted through the same vendor with
`CommitGroupComposition` and `ResetGroupComposition`. It builds an ordered,
scene-owned hierarchy from explicit capture and Solar-band scene-item references;
the plan is validated before the current front is replaced. Source-removal
callbacks enqueue their graph cleanup while libobs is rendering. During normal
`obs_shutdown`, libobs stops and joins its graphics thread before unloading
modules, so `group_composition_unload` first disconnects and drains source-removal
callbacks, releases any removal-event payload still owned by the stopped task
queue, then releases the remaining graph under the still-live graphics context
directly. It must not wait on a graphics task after that thread has stopped.
Non-null coverage masks, non-normal group blend modes, and affine shear are
currently refused before the active graph is changed.

`scripts/probe-group-composition.py` uses a disposable private runtime and
synthetic sources to check ordered capture/Solar-band pixels, successive
commits, reset, source removal, UUID recreation, and shutdown cleanup. Its
`--shutdown-control-only` mode starts the same isolated host without a
composition to distinguish module shutdown from composition teardown. The
probe does not exercise a physical capture device, public output, transition,
or scene switch.

The post-stop pending-removal check is deliberately synthetic: after libobs has
stopped the graphics thread, a test-only helper removes a retained private
source and forwards that source pointer through the global `source_remove`
signal to the plugin's real listener. The latest run recorded one pending event
at capture-plugin unload and released it there. This exercises payload ownership
at the stopped-queue boundary; it is not evidence that ordinary private-source
removal emits the global signal.
