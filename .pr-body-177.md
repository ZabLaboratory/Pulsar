## Summary

`IsDebugEnabled()` (`plugins/pulsar-websocket/src/obs-websocket.cpp:181-184`)
returned `!_config || _config->DebugEnabled` -- fail-open: whenever `_config`
is null (before the config finishes loading, or after `obs_module_unload()`
sets it back to null), the function returned `true` regardless of any actual
debug setting. `blog_debug()` (`plugin-macros.h.in:25`) then logs at OBS'
INFO level, so during those windows the plugin dumped full WebSocket
request/event payloads to the log -- stream key, ingest URL, browser-source
capture URL/show token (`WebSocketServer.cpp:89,421,476`,
`WebSocketServer_Protocol.cpp:408-409`) -- with no debug flag ever
deliberately set.

Fix: flip the null-check so a missing config fails closed
(`_config && _config->DebugEnabled`), matching every other `_config`-guarded
read in this file. One-line change, no behavior change when a config is
actually loaded and `DebugEnabled` is explicitly set.

## Tests

- Added `tests/ws-debug-probe/` (CMake target `ws-debug-probe-test`,
  `ctest` label `pulsar-ws-debug-probe`), wired into the root
  `CMakeLists.txt` next to `tests/nv-probe` under the existing `if(WIN32)`
  block. It mirrors the exact boolean expression at
  `obs-websocket.cpp:181-184` against a minimal stand-in struct and asserts:
  `nullptr` config -> `false`, config with `DebugEnabled=false` -> `false`,
  config with `DebugEnabled=true` -> `true` (behavior preserved when
  explicitly enabled).
- Local build/run (MSVC, isolated `cmake -S tests/ws-debug-probe -B
  build-ws-debug-probe -A x64` + `cmake --build ... --config Debug`,
  executable run directly -- see écarts below for why not the full tree):
  passes (`exit=0`) against the fixed formula; reverting the mirror to the
  old `!config || config->DebugEnabled` formula makes the same probe fail
  its first assert (`exit=3`), confirming the test actually exercises the
  regression.
- Checked `scripts/probe-*.py` and `scripts/run-probes.ps1` for any
  dependency on the current fail-open dump for diagnostic traces: none
  found (`grep -rniE debug` over the probes turns up only unrelated CLI
  flags/log strings, nothing that reads WebSocket debug-level payloads).

## Écarts / hypothèses

- Did **not** attempt a full MSVC build of the whole Pulsar/OBS/Qt tree
  from this worktree -- same limitation noted on a prior task in this repo
  (full local build not reliably reproducible outside the canonical
  checkout's pre-configured tree, which tracks `main`, not this branch).
  Validated the isolated CMake addition (configure + build + run, both
  pass/fail directions) instead; CI (`ctest --test-dir build`, wired into
  `build.yml`) is the first real full-tree build/exercise of this change.
- The regression test duplicates the boolean expression rather than linking
  the real `obs-websocket.cpp` translation unit (Qt/libobs/OBS SDK deps
  make that impractical for a host-only unit test, same constraint as
  `tests/nv-probe`). The mirror is hand-kept in sync via an explicit
  code comment pointing at the exact source lines; no automated link
  between the two.
