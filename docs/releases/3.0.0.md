## [3.0.0] - 2026-09-07

Pulsar 3.0.0 delivers the dual-lane Preview/Program production core, isolated concurrent runtimes, correlated production telemetry, and measured Windows readback improvements. The release includes the TypeScript client and both Windows x64 bundles.

### Scope and comparison baseline

- Previous release: [v2.0.0b](https://github.com/ZabLaboratory/Pulsar/releases/tag/v2.0.0b), commit `514f504db0521035973f576d3ab03788b1b3bf52`.
- Product source reviewed through `3ba9ab8d21eed9f29009fcb6b7b9674643402236` (PR #288); 70 reachable commits since that baseline, including merged branch history.
- Source diff before this release's version/changelog metadata: 268 files changed, 68,231 insertions and 1,115 deletions. These totals include tests, documentation and evidence; they are not a measure of product-code growth.
- [Full release comparison](https://github.com/ZabLaboratory/Pulsar/compare/v2.0.0b...v3.0.0).
- The dual-lane ADR and approved Amendment 1 are closed through #255. Optional extensions retain their documented limitations.

### Added

- **Hot A/B production lanes:** independent physical lanes remain alive while their On-Air and Preview roles alternate. Stable Program and Preview views keep downstream outputs attached throughout a Cut.
- **Frame-boundary atomic Cut:** preparation, admission, commit and abort behavior is exposed through `pulsar.scene-switch.v1`, with command/intent identities, revisions, ordering, stale rejection and idempotent retries.
- **Dual-lane scene-switch runtime:** Preview changes are isolated from Program; preparation freezes the admitted state, and the old On-Air lane becomes editable only after the committed exchange.
- **Fade and Stinger transitions:** dual-lane transition execution and corresponding validation are included. Enable `PULSAR_DUAL_LANE_TRANSITIONS=1` to opt in; the default remains Cut.
- **Runtime isolation:** every Node-spawned process receives a validated `runtimeInstanceId`, private `runtimeDir`, instance lock and dedicated configuration/log/recording namespace. Automatic free-port selection avoids inheriting one shared WebSocket port.
- **Namespaced DirectShow returns:** per-instance queue identities and explicit legacy-alias lease behavior support concurrent runtimes. Legacy aliases remain single-owner resources.
- **Correlated latency instrumentation:** raw Program, DirectShow return, encode requests/completion, output enqueue/interleaver/callback, RTMP receipt and decoded-frame observations have separate boundaries and identities.
- **Configurable telemetry signals:** bounded encoder-stage observations and selector-controlled callbacks allow observation cost to be controlled separately from production optimizations.
- **D3D11 return transport:** an explicitly selected transport, capability reporting, shared-texture path, consumer liveness and CPU fallback diagnostics. Its presence is not a universal performance guarantee.
- **Structured TypeScript diagnostics:** typed transport/runtime errors, canonical action outcomes and optional `onPrismLog` events cover client operations and spawned-runtime lifecycle failures while retaining legacy response fields.
- **Native validation tools:** GPU pending-packet scheduling/failure probes, return-queue concurrency checks, content-timestamp tests and a native RTMP decoder provide reproducible evidence at actual packet/frame boundaries.
- **Operator UX specification and harness:** Preview/On-Air and T-bar interaction, keyboard and accessibility scenarios are documented and exercised in a mock/headless consumer harness. This does not ship a production T-bar UI.

### Changed

- Preserve stable active `video_t` bindings and hot producer activation across lane exchanges, including equal-view swaps.
- Keep Program audio on a common stable route across Cuts. Preview mutation does not switch Program audio implicitly.
- Move DirectShow consumer-lease polling off the per-frame publication path.
- Elide unnecessary Preview/Program return copies when no consumer is active; use bulk copies for tightly packed NV12 planes.
- Pipeline Preview and Program return publication and expose the associated stage costs.
- Reduce selected GPU encoder startup/output waiting and safely lower the existing NVENC ultra-low-latency output delay without reducing codec quality settings.
- **Promote current-frame CPU readback on qualified hardware:** automatic activation is limited to Windows, NV12, 1920x1080, 60/1 fps, CPU encoding and a physical graphics adapter. Other configurations retain the historical path.
- Align current-frame readback presentation timestamps with the audio timeline, keeping content time distinct from encoded/media time.
- Add a guarded Windows incremental-build path covering the frontend API, D3D11 and required native components; allow an explicit upstream build directory and preserve full-build CEF capability.
- Publish `@clodocapeo/pulsar-client`, `@clodocapeo/pulsar-bundle` and `@clodocapeo/pulsar-bundle-full` at 3.0.0, with matching bundle/client dependencies. Internal validation workspaces resolve the same client/runtime generation.

### Fixed

- Reject ambiguous DirectShow queue namespaces instead of attaching to an unintended runtime.
- Resolve libobs data/plugins from the executable location when a process runs from its private working directory.
- Harden shared return queues: validate mappings before atomic reads, retain read-only consumer access, accept committed mapped views and keep NV12 setup/bootstrap live.
- Address CPU mapping and consumer-lease collisions, D3D11 producer/consumer liveness, stale registrations and session cleanup.
- Move consumer registration to producer-owned communication and use a producer-authoritative read-only ABI with authenticated private-helper returns.
- Make pipeline telemetry counters atomic and ensure selectors actually control callback registration.
- Retain valid equal-clock DirectShow stage observations rather than treating finite-resolution zero durations as absent data.
- Preserve Take/frame identities through content-floor validation and renderer catch-up; repeated pictures no longer rely on invalid linear clock-to-media extrapolation.
- Keep decoded marker observations reliable and distinguish packet decode order from presentation order.
- Defer fatal GPU encoder shutdown away from the encoding thread, avoiding a self-wait; verify clean failure followed by restart of the same encoder/output.
- Stop the replay buffer correctly when no timestamp has yet been produced.
- Select process-loopback audio by executable identity.
- Redact the WebSocket password in application-visible startup log callbacks; validate runtime identifiers and clean up owned runtime directories after failed startup.
- Fix Windows fast-build configuration for pristine builds, missing host-processor values, Qt host-tool argument parsing, required headers and patch ordering.

### Measured results and release limits

- Same-observer x264 trials on the qualified Windows 1080p60 workload measured first changed decoded-image p95 at **45.897–45.947 ms before** and **33.045–37.982 ms after**, about **8–13 ms / 17–28% lower**, over 500 measured Cuts plus 500 warm-ups. This is measured decoder output, not physical-display latency.
- Audio validation retained monotonic AAC 48 kHz timestamps over 100 Cuts per codec. All 876 frames in the native/reference decoder comparison matched visible-plane hashes and PTS.
- Three local Twitch broadcasts totaling 245 seconds validated CEF composition, H.264 1080p60, non-silent AAC, public HLS audio/video decode and clean shutdown before release preparation.
- The integrated product revision passed pipeline 34161470883 and compliance 34161471011. Its CTest result was 20 passed, 2 physical-GPU skips and 0 failures. Release-tag validation is recorded separately by the release workflow.
- Preview audio and audio-follow-video are **not supported by this release's dual-lane contract**; the common Program audio route is the supported behavior.
- No universal NVENC decoded-latency gain, 4K qualification, physical-display bound, multi-camera capacity or seamless worker-handoff guarantee is introduced. WGC/CEF/NVENC resource costs remain workload-dependent.
- AC-12a retains the correlated same-packet transport gate. AC-12b is mandatory disclosed command-to-egress timing with no r2 threshold; the two must not be substituted for one another.
- Roll back the qualified CPU staging optimization with `PULSAR_RAW_CURRENT_READBACK=0`. Diagnostic/experimental switches do not imply production qualification.

### Upgrade notes

- Upgrade the client and chosen bundle together to 3.0.0. Use the **full** bundle for browser/CEF sources; the **light** bundle retains its documented reduced module set.
- Code that assumed configuration, recordings or WebSocket state lived beside the executable must use the returned `runtimeDir` or an explicit `PULSAR_RUNTIME_DIR`. Automatically owned runtime directories are temporary and cleaned up at shutdown; use an explicit directory for durable application-owned files.
- Concurrent instances must use their runtime identity and dedicated return names; a legacy DirectShow alias cannot be owned by multiple instances.
- Consumers of scene switching must honor admission/commit events, revisions and idempotency rather than treating request submission as proof of an On-Air change.
- Handle structured error/outcome fields and optionally subscribe to `onPrismLog`; retained legacy fields support existing diagnostic consumers.
